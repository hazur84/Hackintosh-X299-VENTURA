## What's new in EFI-108 (OpenCore 1.0.8, macOS Ventura 13.7.8)

`EFI-108-ASUS-X299.zip` updates `EFI-106-ASUS-X299.zip` (release [OC 1.0.6](https://github.com/hazur84/Hackintosh-X299-VENTURA/releases/tag/OC-1.0-6)) for Ventura 13.7.8. All binaries are the official RELEASE builds (acidanthera and ChefKissInc). The SSDT-X299-BASE, USBMap/ASMedia/X299SATA kexts, HfsPlus.efi, themes and sounds are kept as they were.

| Change | Why |
|---|---|
| Lilu: `MinKernel` 23.0.0 → empty | With 23.0.0 OpenCore only injects Lilu on Darwin 23 or newer (Sonoma and later). On Ventura (Darwin 22) it skips Lilu, and with it VirtualSMC, WhateverGreen, AppleALC and the other plugins. Empty works on every macOS version. |
| `boot-args`: removed `amfi=0x80` and `revpatch=sbvmm,cpuname` | Ventura supports the BCM943602 Wi-Fi and the RX 6600 XT natively, so OCLP and disabling AMFI are not needed. `sbvmm` was only for receiving updates, and 13.7.8 is the last Ventura release. `cpuname` stays in the `revpatch` NVRAM variable (it was duplicated). New boot-args: `-v alcid=1 agdpmod=pikera`. |
| `csr-active-config` 03080000 → 00000000 | SIP enabled. It was only disabled for the OCLP root patches on Sonoma and Sequoia. |
| `SecureBootModel` Disabled → Default | Apple Secure Boot enabled (j137 model of iMacPro1,1), same reason. |
| `ForceAquantiaEthernet` true → false | The Rampage VI Apex has an Intel I219-V (IntelMausi), not Aquantia. |
| `AppleDebug` true → false | Only useful with the DEBUG build of OpenCore. |
| `ResetNvramEntry.efi` added | Since OpenCore 0.8.8 the "Reset NVRAM" entry does not appear in the picker without this driver. |
| New key of OpenCore 1.0.8 | `HideVerbose` on each driver, false. |
| Removed unused kexts | IOSkywalkFamily, RadeonSensor and SMCRadeonGPU (files that were not loaded by the config; SMCRadeonSensors replaces the last two), SmallTreeIntel82576 and SmallTreeIntel8259x (they were disabled). |
| `PlatformInfo` with placeholders | The serial, MLB, UUID and ROM of the previous EFIs were real values published here. EFI-108 ships the OpenCore sample values; generate your own (see [Setup file config.plist](#setup-file-configplist)). |

## Updates or Upgrades:
>[!NOTE]
>This section applies to Sonoma and Sequoia with OCLP root patches (EFI-103 and older). With EFI-108 on Ventura 13.7.8 there is nothing to patch: keep SecureBootModel Default and SIP enabled.

Before install updates, upgrades or apply root patches:
1. Update the last version OpenCore and kexts from EFI foldder with OCAuxiliaryTools. 
2. Change SecureBootModel to disable value. 
1. Change csr-active-config to 03080000 to disable System Integrity Protection (SIP) 
2. Change GateKeeper launching terminal run the following command:
   - sudo spctl --global-disabe
   - In System Settings --> Privacy & Security Page --> Scroll Down to bottom --> Select "Allow Application From" --> Select "Anywhere"
   - sudo spctl --status (check status)

## After successfull update or upgrade you can revert values.
1. Change SecureBootModel to Default value.
2. Change csr-active-config to 00000000 to enable System Integrity Protection (SIP).
3. Change GateKeeper launching terminal run the following command:
   - sudo spctl --global-enable
   - sudo spctl --status (check status)
    
## Notes about software updates

1. Getting Update notification
   - iMacPro1,1 (iMac Pro 27″, late 2017) models do have a T2 chip and, when using these SMBIOS models, you do not receive update notifications
   - iMacPro1,1 models receive update notifications if configured as vmm (virtual machine): revpatch=sbvmm in boot-args along with RestrictEvents.kext.

2. Size of the update (full or incremental)
   - Systems where the OCLP root patch has not been applied or has been reverted:
   - iMacPro1,1 require revpatch=sbvmm in boot-args along with RestrictEvents.kext to get incremental updates, without this setting you get full-size updates
   - All systems that have the OCLP root patch applied receive full-size updates.

After the system is updated, RestrictEvents.kext and the boot argument can be disabled because they are not required for normal operation.

Ventura 13.7.8 is the final Ventura release, so EFI-108 no longer sets `revpatch=sbvmm`. RestrictEvents.kext stays for `revpatch=cpuname` (CPU name in About This Mac).

## What's not working?
Fenvi T919 Wi-Fi: macOS Sonoma has dropped support for all Broadcom Wi-Fi present on Macs before 2017. Fenvi T919 and HB1200 have BCM4360 chipsets (not supported) so Wi-Fi does not work in Sonoma. Bluetooth works fine. This is a serious inconvenience because functions related to the Apple ecosystem (Airdrop, Continuity Camera, etc.) are also lost. The only option to fix is using OCLP patch.

On Ventura these Broadcom cards (BCM4360 and BCM943602) still work natively, without OCLP.

### NVMe drive on a PCIe adapter not detected

NVMe drives do not appear in the SATA list of the BIOS; look in the Boot menu ("UEFI OS (...)"). If the drive does not appear anywhere, check:

1. That the PCIe slot and the adapter contacts are clean. A dirty PCIe connector was the cause on this build.
2. The **PCIEX16_SW** DIP switch (4 levers, top right, next to the 24-pin power connector). Each lever enables or disables one PCIe x16 slot; all of them must be ON.
3. Advanced → CPU Storage Configuration: do not set the adapter slot to "Hyper M.2 X16" for a single-drive adapter. In the manual that option belongs to Intel VROC/VMD RAID, and macOS cannot see drives behind VMD.
4. With a 44-lane CPU, put the GPU in PCIE_X16/X8_1 and the adapter in PCIE_X16/X8_3 (both x16). The M.2_2 socket of the CPU DIMM.2 card is disabled when Advanced → Onboard Devices Configuration → PCIEX8_4 Switch Function is set to x8 mode.

The onboard Intel Wi-Fi 802.11ac is not used by macOS; it can be disabled in Advanced → Onboard Devices Configuration.

## Setup file config.plist

You will need to create your own Serial Number and SMUUID. Instructions can be found [here](https://dortania.github.io/OpenCore-Install-Guide/config-HEDT/skylake-x.html#platforminfo). Remember to adjust the SMBIOS a iMacPro1,1

EFI-108 ships placeholders in `PlatformInfo → Generic` (SystemSerialNumber `W00000000001`, MLB `M0000000000000001`, SystemUUID `00000000-0000-0000-0000-000000000000`, ROM `11:22:33:44:55:66`). Replace them before signing in with your Apple ID:

- Serial and MLB: `macserial -m iMacPro1,1 -n 1` (in `Utilities/macserial` of the [OpenCore release](https://github.com/acidanthera/OpenCorePkg/releases)) or [GenSMBIOS](https://github.com/corpnewt/GenSMBIOS). Check the serial at [checkcoverage.apple.com](https://checkcoverage.apple.com): it must come back as not valid.
- SystemUUID: `uuidgen` in Terminal.
- ROM: the MAC address of en0 (Intel I219-V), `ifconfig en0 | awk '/ether/{print $2}'`.
- Validate the result with `Utilities/ocvalidate config.plist` from the same OpenCore release.

## Fix black screen with RX6X00 (6600; 6800; 6900) on Ventura or higher 
- Use iMacPro1,1 SMBIOS
- **agdpmod=pikera** in boot args. 
- Add in DeviceProperties of config.plist properties that set Henbury framebuffer for each of the 4 ports of this GPU.

<img width="956" alt="Screenshot 2023-01-06 at 11 57 31" src="https://user-images.githubusercontent.com/8379954/211070820-06f5ce09-feb8-4646-b36f-c474d2e2ec1c.png">

By default, Radeon framebuffer (ATY,Radeon) is loaded. But, in AMDRadeonX6000Framebuffer.kext >> Contents >> Info.plist we can see that AMDRadeonNavi23Controller has ATY,Henbury and 6600 series are Navi 23. This is why this framebuffer is selected.

The patch is added in this way:

<img width="961" alt="Screenshot 2023-01-06 at 11 44 37" src="https://user-images.githubusercontent.com/8379954/211068826-b8cc5216-a3d7-4de2-9ffe-ce89935ac110.png">

```js
<key>DeviceProperties</key>
    <dict>
        <key>Add</key>
        <dict>
            <key>PciRoot(0x1)/Pci(0x0,0x0)/Pci(0x0,0x0)/Pci(0x0,0x0)/Pci(0x0,0x0)</key>
            <dict>
                <key>@0,name</key>
                <string>ATY,Henbury</string>
                <key>@1,name</key>
                <string>ATY,Henbury</string>
                <key>@2,name</key>
                <string>ATY,Henbury</string>
                <key>@3,name</key>
                <string>ATY,Henbury</string>
            </dict>
        </dict>
        <key>Delete</key>
        <dict/>
    </dict>
```

Notes:

PCI path to the GPU may be the same on your system but it is convenient to check it with [Hackintool](https://github.com/benbaker76/Hackintool)

>[!IMPORTANT]
>The config.plist of EFI-099 to EFI-108 uses the key `PciRoot(0x1)/Pci(0x0,0x0)/Pci(0x0,0x0)` (3 levels), while the path above has 5 levels. If your GPU is at the 5-level path, the Henbury property is not applied and the screen works only thanks to `agdpmod=pikera`. Check the real path with Hackintool or [gfxutil](https://github.com/acidanthera/gfxutil) and adjust the key.

## Problems with USB ports

Please use [this](https://dortania.github.io/OpenCore-Post-Install/usb/intel-mapping/intel.html) as a proper guide to map your USB ports.

>[!WARNING]
>The `USBMap.kext` included in the EFIs has `model = MacPro7,1`, but the SMBIOS is iMacPro1,1, so macOS ignores the map. It also declares 18 ports on the XHCI controller, and the macOS limit is 15. Until it is redone (for example with [USBToolBox](https://github.com/USBToolBox/tool), for iMacPro1,1 and at most 15 ports per controller), macOS uses the first 15 ports reported by the board. `XhciPortLimit` stays false.

## Compatibility with macOS Sonoma (14) and Sequoia (15)

EFI-108 is tested on **macOS Ventura (13.7.8)**, but it can also be the base for **Sonoma** and **Sequoia**: the RX 6600 XT (Navi 23) keeps native graphics support in both versions, and the **iMacPro1,1** SMBIOS is still supported up to Sequoia (macOS 26 Tahoe dropped it).

What to change for Sonoma or Sequoia:

1. **Updates:** iMacPro1,1 has a T2 chip, so Software Update does not offer new versions. Add `revpatch=sbvmm` to `boot-args` (RestrictEvents.kext is already included). See [Notes about software updates](#notes-about-software-updates).
2. **Wi-Fi (Broadcom BCM943602):** Apple removed the Broadcom Wi-Fi drivers starting with Sonoma, so Wi-Fi stops working. To get it back you need the root patches of [OpenCore Legacy Patcher](https://github.com/dortania/OpenCore-Legacy-Patcher), with the same settings as EFI-106: `csr-active-config` 03080000 (SIP partially disabled), `SecureBootModel` Disabled and `amfi=0x80` in `boot-args` (or AMFIPass.kext). Follow the [Updates or Upgrades](#updates-or-upgrades) section. Ethernet (IntelMausi) and Bluetooth keep working without patches.

Other points to check:

- **Kexts and OpenCore:** EFI-108 already has the latest versions (OpenCore 1.0.8, Lilu 1.7.2, WhateverGreen 1.7.1, AppleALC 1.9.8, VirtualSMC 1.3.8). Update them again before a future macOS update.
- **Backup:** make a copy of the EFI that works and test the new one from a USB before changing the one on the disk.

> ⚠️ EFI-108 has not been tested on Sonoma or Sequoia on this machine. EFI-106 (release [OC 1.0.6](https://github.com/hazur84/Hackintosh-X299-VENTURA/releases/tag/OC-1.0-6)) was tested OK on Sequoia 15.7.4. If you try EFI-108 on Sonoma or Sequoia, open an *issue* to share the result.
